# 画面・機能の範囲と担当分け

デモシナリオ（`docs/demo-scenario.md`）に出てくるものを作る。出てこないものは作らない。

## 画面

### 公開側（観光客）

- `/m/:mapId`: ヘッダー画像・タイトル・説明文、地図とスポットのピン、レイヤー切替
- スポット詳細（経路ボタンつき）。掲載期間外のスポットは出さない
- 公開終了ページ

### 管理側（職員）

- `/admin/login`: ログイン
- `/admin`: マップ一覧
- `/admin/maps/:id`: マップ編集。LP 設定（タイトル・説明文・ヘッダー画像）、レイヤーの追加・名前変更・削除、スポット一覧
- スポット編集: 名前、説明、所属レイヤー（チェックボックス）、掲載期間（任意。入れると臨時スポット）。位置は地図をクリックしてピンを置き、ドラッグで調整する
- `/admin/maps/:id/qr`: レイヤーを選んで QR を出し、印刷用レイアウトで表示

### データ

`maps` / `layers` / `spots` / `spot_layers`（多対多）/ BetterAuth のテーブル

### 作らない

- 職員アカウント管理画面（seed で作る）
- スポットの画像（LP のヘッダー画像のみ）
- LP のセクション構成の自由編集（時間が余れば）
- 権限の区別（ログインした職員は全マップを編集できる）
- 住所検索（ピンを置く方式で足りる）

## 進め方

- 橋本が先に雛形を作り、部品の置き場所と仮データを用意する
- メンバー1・2 は仮データを props で受け取って表示する部品だけを作る。DB・API には触らない
- 担当ごとにファイルを分けてコンフリクトを避ける
- 担当ごとのブランチから PR を出し、橋本がマージする。Claude Code などの AI を使ってよい
