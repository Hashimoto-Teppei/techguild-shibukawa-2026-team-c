# 発表資料・台本

Issue #54 の7分枠に合わせた発表案。スライド約4分30秒、ブラウザーの短縮デモ約2分30秒。ログイン・登録から新規マップ公開までを通す約5分の詳細台本は `docs/demo-scenario.md` に記載。実際の利用者への効果検証は未実施なので、課題や期待効果は仮説として伝える。

## 伝えること

- **チーム名:** カメに懸賞金（チームC）
- **作品名:** たまりんマップ（作品情報シート記載の名称）
- **一言:** たまのじゃない、いつでもたまらんマップ
- **課題:** 観光・地域情報が複数の場所に分散すると、来訪者は目的に合うスポットや設備を探しにくく、情報を発信する側にも整理・更新の負担がある。
- **解決:** 作成者がスポットを地図と目的別レイヤーに登録して公開し、閲覧者はログインせずにマップやQRから情報を見つけられる。
- **デモ:** https://techguild-shibukawa-2026-team-c.hashimoto-2f0.workers.dev

## 発表の流れ

1. **タイトル（20秒）**
   「チーム『カメに懸賞金』の、たまりんマップです。たまのじゃない、いつでもたまらんマップを目指しました。」
2. **課題と作品紹介（60秒）**
   「ビーチスポーツ体験会を開くとき、参加者に会場設備や持ち物、当日の案内を分かりやすく届ける必要があります。たまりんマップでは、地域の作成者がスポットと目的別の情報をまとめて公開できます。」
   課題の提示は利用者への聞き取り結果ではなく、今回の提案として説明する。
3. **サービスの機能（60秒）**
   誰でもマップを公開でき、閲覧者はログイン不要です。レイヤーで目的別にスポットを見せ分け、掲載期間を過ぎた臨時スポットは自動で非表示にします。マップページはヘッダー画像と説明文で案内に使え、レイヤーごとに固定 URL の QR を発行できます。経路ボタンから Google マップを開けます。
4. **ブラウザーでデモ（2分30秒）**
   ログイン画面で登録・ログインの入口を見せ、公開トップで「見る人はログイン不要、作る人は自分で公開」を説明する。大会デモマップでは参加者向け・会場設備・開催準備・安全救護から1スポットずつ紹介する。管理画面では「マップ作成→レイヤー→スポット→公開」の流れを操作し、時間に応じて入力済みの非公開マップを使う。詳細な発話と手順は `docs/demo-scenario.md` に沿う。
5. **技術と設計（90秒）**
   Vite / React の SPA と Hono の API を1つの Cloudflare Worker で動かし、D1 にデータ、R2 に画像を保存しています。公開 URL の ID は作成後に変えず、レイヤーの ID を使うため、名前を変えても配布した QR を維持できます。期間外スポットは公開 API から除きます。管理 API は作成者の ID で所有マップを絞ります。
6. **まとめと今後（40秒）**
   「参加者には必要な案内をまとめて届け、作成者は自分で情報を更新できます。開催条件や設備を確認しながら、渋川でのビーチスポーツ体験を案内する方法を提案します。」

## 作品情報シート記入案

- **主な機能:** ①作成者がマップやスポットを登録・公開し、自分で更新 ②閲覧者はログイン不要で、目的別レイヤーからスポットや設備情報を検索 ③臨時スポットの掲載期間設定と、マップごとのQR発行
- **工夫:** 閲覧者はログイン不要。1つのスポットを複数のレイヤーに登録できる。掲載期間を過ぎた臨時スポットは自動で非表示。配布したQRのURLは維持する。
- **技術:** Claude Code（開発支援）、TypeScript、React、Vite、Hono、Drizzle、BetterAuth、Cloudflare Workers / D1 / R2、Google Maps Platform、qrcode.react
- **できたこと:** 公開マップ一覧・閲覧ページ、作成者の登録／ログイン、マップ・レイヤー・スポットの管理、掲載期間による臨時スポットの自動非表示、QR発行・印刷ページを実装し、Cloudflare Workersに公開。実利用者による検証と発表リハーサルはこれから。
- **残課題:** 発表資料の完成と全員リハーサル、地域の作成者・閲覧者による使いやすさや運用方法の検証。
- **発展案:** 地域の作成者へのヒアリングを通じた情報項目・更新手順の改善、実際のイベント情報を使った運用、利用状況の確認。

## 発表時の注意

- 「観光客が増える」などの効果は検証していないため、実績として言わず、期待する価値として説明する。
- デモ用スポット・イベント情報は動作説明用のサンプル。ビーチスポーツ大会マップは架空の説明用データで、開催・募集情報ではない。設備、海岸利用、救護、気象・海況の中止基準は仮置きで、協会と管理者の確認前に確定情報として案内しない。
